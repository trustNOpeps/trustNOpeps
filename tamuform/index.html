The design starts with a practical question. What happens after someone asks about a service?

Tamuform brings the public inquiry and the internal follow-up into one workflow. The website explains the offer, while the workspace gives each inquiry a stage, a follow-up date and a place for notes.

This is a product hypothesis explored through design and implementation. Customer adoption, conversion improvements and revenue have yet to be measured.

THE WORKFLOW

From interest to action.

  1. Discover

    Understand the studio’s services through a bilingual website.

  2. Inquire

    Provide business context, service needs and consent to be contacted.

  3. Qualify

    Review the inquiry and move it through contacted, qualified and proposal stages.

  4. Follow up

    Add internal notes, set a date and record a won or lost outcome.

IMPLEMENTATION

Small product.
Connected workflow.

The application uses Python and FastAPI, server-rendered Jinja templates, and CSS with small JavaScript enhancements. SQLite supports local development; PostgreSQL is the configured cloud data store.

The private implementation includes authenticated administration, TOTP MFA, form validation, consent capture, follow-up editing and protected CSV export. These controls were identified in the source. This case study does not certify their production operation.

EVIDENCE & CURRENT SCOPE

What this project demonstrates.

Delivered

A bilingual website design, inquiry workflow and private CRM implementation. This public case study includes source-based interface previews and a browser-only example walkthrough.

Still to validate

A live cloud deployment, end-to-end admin login, persisted inquiries after restart and real user feedback. Booking, payment processing and multi-tenant account management are outside the implemented pilot.
